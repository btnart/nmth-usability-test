# 假設型 persona：週末帶孩子來的家長（v1）

<sub>2026-11-09 建立｜依據 `user-journey-nmtl-webguide.md`</sub>

> 這份是**假設型 persona**。內容是從旅程地圖 v3 推論的，旅程地圖的來源是 5 場館員訪談，**我們沒有訪談過觀眾本人**，不能當成研究結論。每一條後面標了來源：【館員】＝館員轉述，【官網】＝臺史博官網，【測試】＝第 1 輪易用性測試，【推測】＝沒有一手資料。

## 林育庭｜38 歲，帶 7 歲的孩子週末來館

**一句話：**「我只想讓孩子玩得開心、不要累壞，又不想錯過要排隊的東西。」【推測】

### 什麼時候打開導覽、想完成什麼

- **進門前後：** 剛刷票進大廳，要決定先去兒童廳還是常設展，還要搞清楚時光車站要不要預約、VR 幾點開始。【館員】假日時光車站要開館後到現場預約【官網】
- **逛展中：** 孩子被亮光模型、水牛、玩水人像吸引，育庭想快速找到「孩子會有興趣的那幾站」，不是每一站都聽。【館員】
- **離館時：** 孩子累了，想馬上找到出口和廁所。【館員】【測試】

### 一起來的人

- **孩子（共同使用者）：** 7 歲，沒有自己的手機，跟育庭共用一支手機和耳機，兩個人不能離太遠。【館員】
- **導覽由誰操作：** 一手牽孩子、一手滑手機，常常只能用單手、只有幾秒鐘可以看螢幕。【推測：館員看不到這個情境】

### 會做的決定 → 需要的資訊 → 卡住會怎樣

| 決定 | 需要的資訊 | 卡住會怎樣 |
|---|---|---|
| 先去哪裡 | 今天每項活動的場次、怎麼參加、在幾樓 | 錯過時光車站的預約，孩子吵著要玩【館員】 |
| 往哪裡走 | 自己在哪裡、目的地在哪個方向 | 找不到服務台、以為有 3 樓、搭到 4F 找不到特展室【館員】 |
| 要聽哪幾站 | 適合孩子的站、每站多長 | 孩子逛到戰後展區就累了，後面都沒看【館員】 |
| 什麼時候走 | 出口在哪、廁所在哪 | 習慣從進來的 8 號門出去，被擋下來繞路【館員】 |

### 讓育庭不舒服的地方

- **排程焦慮：** 時光車站、圓形劇場、VR、兒童廳的規則都不一樣。【館員】
- **耳機：** 沒帶耳機，只能外放，又怕吵到別人。【館員】
- **號碼貼紙：** 太小、被摳壞，找不到第幾站。【館員】

### Web 導覽能幫上忙的範圍

- **導覽能處理：** 本日活動和參加方式、地圖與帶我去、出口指引、耳機提醒、適合孩子的路線。
- **導覽處理不了：** 停車場被導錯、團體票綁定導覽設備、館內餐飲少。這幾項要靠現場營運，不算在這個 persona 的設計範圍。

## 待驗證的假設

1. **共用操作：** 家長真的是一手牽孩子、一手單手操作嗎？用**現場觀察**驗證。
2. **有沒有人用：** 親子家庭會打開 Web 導覽嗎？還是只跟著孩子走？看**上線後的使用數據**，或到兒童廳門口做短訪。
3. **排程功能：** 「幫我排今天的順序」真的能減少排程焦慮嗎？下一輪**易用性測試**請親子受測者試。

## 使用前要先確認

- **主要 persona 選誰：** 樂齡、平權觀眾可能是標案評分的重點。要先問 PM 標案最看重哪一類觀眾，再決定親子家長是不是主要 persona。
- **功能範圍：** 排程助手、兒童版選件在不在標規版的範圍內，要查清楚。
- **痛點多不等於主要使用者：** 親子家長的痛點橫跨 5 個階段，但其中一部分 Web 導覽解決不了，已在上面分開列出。
